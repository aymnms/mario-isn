# Plan — mario-isn

> Ce fichier est la seule source de vérité de l'avancement. Il doit refléter la réalité à tout moment. Commit à chaque mise à jour.

## Raisonnement du découpage

Les jalons suivent directement les 4 issues GitHub ouvertes, dans l'ordre de dépendance et d'effort identifié en `AUDIT.md` §7. J1 (fix release) est traité en premier car il bloque toute distribution du projet et est de faible effort/risque isolé (un seul paramètre CI, cf. AUDIT.md §4-5). J2 (bundling des libs) est ensuite nécessaire pour qu'une release distribuée soit réellement utilisable (AUDIT.md §4, #15). J3 (Windows) est traité en dernier car c'est le chantier le plus large (nouveau job CI jamais validé, cf. AUDIT.md §3) et le moins bloquant dans l'immédiat (aucune régression actuelle, juste une plateforme absente).

### Plan d'extraction domain — J14+

Ordre par risque croissant, chaque phase sur sa propre branche, TDD strict :

1. **`goM()` (goombas)** — extraire la détection de collision sur le modèle de `domain_classify_tile()` déjà fait pour `go()` ; plus simple que `go()` (pas de réactions différenciées, juste bloqué/pas bloqué). Risque faible, effort faible.
2. **`goB()` (Bowser)** — même extraction, fichier le plus complexe et le moins testé du dépôt, mais bien compris après deux débogages (`J11`, `J12-4`). Risque moyen, effort moyen.
3. **Machine à états saut/chute** (`saut_joueur.c`) — les formules pures existent déjà (`domain_jump_arc`), pas les transitions (déclenchement de la chute, atterrissage). Risque moyen, effort moyen.
4. **Parsing de `niveau.lvl`** (`niveauSelect()`) — extraire le décodage du format `#<niveau>...@` en fonction pure opérant sur une chaîne plutôt que sur un `FILE*`, testable sans fichier réel. Risque moyen, effort moyen.
5. *(optionnel, plus gros)* **`game_over()`/`victory()`** (`conditions.c`) — séparer la transition d'état du séquencement d'animation (`SDL_Delay`). Risque élevé, effort élevé — à ne faire que si les phases précédentes se passent bien.

- **J13** — Utilisateur redemande un audit de code (deuxième agent indépendant, cette fois avec pour consigne explicite de traquer le même type de bug que `BSSO`/`BSO` ailleurs dans le dépôt). Rien trouvé de ce côté, mais trouvaille bien plus significative : la boucle `main()` qui permet de revenir au menu après une partie est commentée depuis toujours (`quit_game()` — dont le commentaire dit littéralement "redirection Menu" — ferme en réalité tout le programme). Confirmé par lecture directe avant d'agir, sur demande explicite de l'utilisateur. La réactivation naïve de cette boucle aurait introduit deux nouveaux bugs (fenêtre/rendu/audio recréés à chaque retour au menu ; fermeture de fenêtre au menu qui ne fermait jamais vraiment l'appli) — corrigés dans la même passe. Conséquence directe : le smoke test Linux et le test de fuite mémoire (`J10-2`) exploitaient tous deux ce bug (`SIGTERM` au menu ne fermait pas vraiment l'appli) pour entrer dans le jeu sans simuler de clic — remplacé par un vrai point d'entrée de test explicite (`MARIO_ISN_AUTOPLAY`).
